# アフロCMS（仮称）— インタラクティブデモ

Web サイトの **営業・要件定義・制作・品質管理・運用・改善** を一元管理する、AI 搭載型 Web 制作プラットフォームの操作デモです。
社内説明・営業プレゼン・操作体験のためのもので、**本番システムではありません**。

> - バックエンドなしで動きます。データはすべて架空のモックで、操作の結果は **このブラウザの localStorage** にだけ保存されます
> - **AI 機能はすべてシミュレーション**です。事前に用意した結果を段階的に表示しているだけで、外部 AI・外部 API への送信は一切行いません（画面には「AIシミュレーション」と表示）
> - 業務要件の一次資料: `アフロCMS草案.pptx`

## 公開URL

https://kazumasaueno.github.io/afro-cms-demo/

GitHub Pages で公開しています。`main` へ push すると、GitHub Actions（`.github/workflows/pages.yml`）が型チェック・ビルド・公開を自動で行います。

## 起動手順

必要なもの: Node.js 20 以上（動作確認: 22.14.0）

```bash
npm install
npm run dev        # 開発サーバー → http://localhost:5180
```

本番ビルドで確認する場合:

```bash
npm run build      # 型チェック（tsc）＋ ビルド
npm run preview    # → http://localhost:4173
```

デモを最初の状態に戻すには、画面右上の「↺」（または 設定 / プレゼンモードの最後のスライド）から **デモを初期化** を押します。

### ログイン（デモ）

画面は立場ごとにログインが分かれています。未ログインの画面を開くと、その画面のログインへ移動し、ログイン後に元の画面へ戻ります。
**デモのため実際の認証は行いません**（入力内容はどこにも送信されず、ログイン状態だけをこのブラウザに保存します）。

| 画面 | ログイン画面 | デモ用アカウント（入力済み） |
|---|---|---|
| 管理者画面 | `/login` | `ueno@afro.example`（上野 航） |
| 開発者画面 | `/dev/login` | `kuroda@afro.example`（黒田 蓮） |
| お客様ポータル | `/portal/login` | `tanaka@minamo-coffee.example`（ミナモ珈琲 担当者） |

- パスワードは `demo-pass`（入力済み）。空でなければどの値でも通ります。メールアドレスは形式だけ確認します
- 次に二段階認証の確認コードを入力します。デモ用コードは `123456`（どの 6 桁の数字でも通ります。「コードを再送」は表示だけ）
- ログアウトは上部バーの右端のボタン。**今いる画面だけ**からログアウトします
- 「デモを初期化」してもログイン状態は消えません（デモデータとは別に保存しています）
- 営業プレゼンモード（`/present`）はログインなしで開けます

## 技術構成

| 領域 | 採用 |
|---|---|
| 基盤 | React 18 / TypeScript / Vite / React Router 7 |
| UI | MUI v5 + Emotion（独自テーマ `src/theme`）/ Lucide React / Inter + Noto Sans JP（同梱） |
| 動き | Motion for React（ページ・カード・モーダル）/ GSAP（ステップ演出・タイムライン） |
| 機能 | React Flow（サイトマップ）/ Tiptap（リッチテキスト）/ Recharts（グラフ） |

- Tailwind CSS は使っていません
- Swiper・dnd-kit は導入していません（比較・カルーセルは CSS scroll-snap、ドラッグ操作は React Flow で足りたため）
- React Router は v6 系に既知の脆弱性（moderate 2件）があったため v7 を採用しました（API はほぼ同じ）
- GSAP と Motion は **同じ DOM 要素を同時に動かさない** 分担にしています（`docs/DESIGN.md`）

## 画面と実装済み機能

画面は **立場ごとに 3 つ** に分かれ、それぞれにログイン画面があります（上の「ログイン（デモ）」）。ログイン後は上部バーの「画面の切り替え」ボタンで行き来でき、まだログインしていない画面を選ぶとそのログイン画面へ移動します。

| 画面 | 使う人 | パス | 内容 |
|---|---|---|---|
| **ログイン** | 全員 | `/login` `/dev/login` `/portal/login` | 画面ごとのログイン（メールアドレス・パスワード → 二段階認証の確認コード）。デモ用アカウントとコードを画面に表示。ほかの画面のログインへのリンク |
| **管理者画面** | アフロ社内 | `/` 以下 | 案件・要件・制作・品質・改善を進める（下の表の 1〜6・8・9 と設定） |
| **お客様ポータル** | お客様 | `/portal` 以下 | ホーム（進み具合・公開予定・お願いしたいこと・サイトの更新・担当者・最近の動き）、ヒアリング（`/portal/requirements`。お客様の担当の質問への回答・アフロが代理入力した回答の確認・アフロの担当の質問への追記。AI 分析後は締め切り）、確認・承認（要件定義書・サイトマップ・トップデザインの承認。デザインは 3 案から選ぶ）、品質確認（お客様側のチェック・カテゴリごとの一括確認）、ページ・お知らせ（`/portal/pages`。下の表の 7）、公開承認（`/portal/publish`。承認待ちの更新をプレビュー・比較して「承認して公開」または「コメントを付けて差し戻す」、承認の履歴）、レポート（KPI・改善レポートの閲覧とダウンロード）、サイネージ（`/portal/signage`。店頭の画面に流すコンテンツ〔おすすめ・メニュー・お知らせ。公開中のお知らせからも作れる〕を作り、端末ごとに流す内容と順番を選んで配信。端末のオンライン状態・未配信の変更・再生プレビュー。デモのため実際の端末には接続しない）。全画面の右下に AI アシスタント（画面ごとの案内・よくある質問への回答。シミュレーション） |
| **開発者画面** | アフロ制作エンジニア | `/dev` 以下 | ダッシュボード（タスクの件数・3 環境の最新版・最近のデプロイ・最近のエラー〔デモデータ〕）、構築タスク（ページごとの未着手 / 作業中 / レビュー待ち / 完了、自分の担当のみ表示）、自動チェック（品質チェック A 区分をアフロ側で一括確認・計測スコア〔シミュレーション〕）、環境・デプロイ（開発 → 検証 → 本番。本番は検証環境が最新かつトップデザイン承認済みのときだけ。シミュレーション） |

- 旧 `/cms` 以下の URL は `/portal/pages` へ転送します
- 開発者画面での操作は「黒田 蓮（エンジニア）」の操作として記録されます
- お客様の画面での操作は「ミナモ珈琲 担当者」の操作として記録され、管理者画面のアクティビティ・承認履歴・各画面の承認状態に反映されます

## 未実装（今回の対象外）

- 実際の認証・権限設定（草案「その他」）。ログインと二段階認証は画面の流れだけで、パスワード・確認コードは照合しません。ログイン状態はブラウザ内の表示の切り替えで、権限による制限（セキュリティ上の保護）ではありません
- 実際の AI 生成（分析・デザイン生成・ディスクリプション生成・サイト診断はすべてシミュレーション）
- 実際の Web サーバーへの公開（公開・予約公開はデモ上の状態変更のみ。予約時刻になっても自動では公開されません）
- 素材ドライブ、フォーム管理、ページ履歴管理、実際のアクセス解析との連携
- レポートの自動送信（設定のトグルは見た目だけ）
- Firebase などのバックエンド接続、本番デプロイ
- プロジェクトごとの個別データ（要件・サイトマップ・デザイン・CMS のデータは MINAMO COFFEE の 1 案件分だけ持っています）
- CMS のページ削除
- 81問・110問・60問の全文（構造と件数は持っており、実際に操作できるのは代表の質問・項目です。品質チェックは 58 項目を収録）

## ディレクトリ構成

```
src/
  types/        ドメイン型（Firebase 移行時はこの形をドキュメントとして使う想定）
  data/         モックデータ（UI から分離）
  services/     localStorage の安全な読み書き・日時
  store/        状態（useReducer + Context）。保存は 250ms にまとめて書き込む
  theme/        デザイントークンと MUI テーマ
  components/   共通 UI（ui/）とレイアウト（layout/）
  hooks/        reduced motion・トースト・ブレークポイント
  features/     画面ごとの実装
docs/DESIGN.md  デザインシステムと動きの分担
```

### Firebase へ移行するとき

UI は `useDemo()`（`src/store/DemoStore.tsx`）だけを通して状態を読み書きしています。
`src/services/storage.ts` と `DemoStore` の読み込み・保存部分を Firestore の repository に差し替えれば、画面側はほぼそのまま使えます。
日時は ISO 文字列で持っているため、Timestamp への変換は repository 層で行ってください。
