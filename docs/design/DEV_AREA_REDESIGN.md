## 全体（G）

### G1 【P1】エリア色 #7C5CFA をボタンに使わない
- 問題: `DESIGN.md` で accent（#7C5CFA）は「AI 関連の印だけ」。開発者画面はエリア色＝accent を主要ボタンの塗りに使っている（`DevChecksPage.tsx:72` 実行ボタン、`:82` 進捗バー、`DevDashboardPage.tsx:124` 枠線ボタン、`DevDeploysPage.tsx:60` 本番カード枠）。白文字とのコントラストは**約 4.4:1 で AA（4.5:1）未達**（14px 600 は大きい文字に該当しない）。管理者ホームの主要ボタンは primary（#3B5BDB、約 5.7:1）なので、ページ間で主要操作の色もずれている
- 変更: 上記 4 か所の `AREA.color` 上書きを削除し、MUI テーマの既定（primary）に戻す。エリア色はサイドバー・上部バーのエリア印だけに残す（`nav.ts` は変更しない）
- `devUi.ts` の `ENV_TONE.production: 'accent'` → `'primary'`（本番＝AI ではないため）

### G2 【P1】技術的な識別子を等幅にする（`DevMono`）
- 問題: バージョン（`v0.9.3`）・環境 URL が本文と同じ字形で、一覧で桁が揃わず「道具」に見えない。アプリ内では既に `tokens.font.mono` を URL・パスに使っている（`Sidebar.tsx:101`、`SitemapPage.tsx:171`）のに開発者画面だけ未使用
- 変更: `src/features/dev/DevMono.tsx` を新設（機能内の小部品。共通 ui には入れない）
  - `<DevMono size="lg|md|sm">` → `fontFamily: tokens.font.mono`、`fontVariantNumeric: 'tabular-nums'`、`letterSpacing: 0`、size: lg 22px/700、md 14px/600、sm 12px/500（color `tokens.color.muted`）
- 適用先: 全ページのバージョン表示、環境 URL、デプロイ履歴の日時（sm）。**本文・見出し・ボタン文言には使わない**

### G3 【P1】状態を色付き文字で書かない（コントラスト不足）
- 問題: 本番ゲートの理由文 `tokens.color.warning`（#C27803）12px は白地で**約 3.5:1**（`DevDeploysPage.tsx:78`）。ダッシュボードの「失敗」`tokens.color.danger` は**約 4.4:1**（`DevDashboardPage.tsx:91`）。どちらも本文基準 4.5:1 未達
- 変更: 文字色は `tokens.color.inkSoft` に統一し、状態は `StatusPill`（色＋文字。既に AA を満たす fg を持つ）かアイコン（非テキスト 3:1 で可）で示す
  - 失敗 → `<StatusPill tone="danger">失敗</StatusPill>`
  - ゲート理由 → 行頭に `Lock` アイコン 16px（`tokens.color.warning`）＋ 理由文 `inkSoft` 13px

### G 共通の守り（P1 の実装時に同時に満たす）
- タップ対象 44px 以上（環境 URL リンクは現在 32px：`DevDashboardPage.tsx:70` → `minHeight: 44`）
- `Reveal` 以外の新しい演出を足さない。開閉は `Collapse` を使い、`useReducedMotion()` が真なら `timeout={0}`
- 「デモデータ」「シミュレーション」の表示は今の位置のまま残す（削らない）

## /dev ダッシュボード

**Primary Action**: 「次にやること」カードのボタン 1 つ（ヘッダーの「自動チェックへ」は削除）

### D1 【P1】件数カード 4 枚 →「次にやること」＋「あなたのタスク」
- 問題（1440 / 390）: 最上段が 4 枚の件数カード（未着手 3 / 作業中 2 / レビュー待ち 2 / 完了 2）。390px では**最初の画面のほぼ全部（約 400px）を件数だけが占め**、操作できるものが無い。「今日の作業」という見出しなのに自分の作業一覧が無い。ヘッダーの主要ボタンが「自動チェックへ」で、今やるべきこと（下記の例では検証環境への反映）と一致しない
- 変更（上から順）:
  1. **次にやること**（`Surface`、padding `{xs: 2.5, md: 3}`。AI ではないのでグラデーション・`AiMark` は使わない。左に 40px の丸地アイコン `bgSubtle`）
     - 判定（既存 state だけで決まる。上から最初に当てはまるもの 1 件）
       1. 開発環境の最新デプロイが失敗 →「開発環境のビルドが失敗しています」／「デプロイ履歴を見る」→ `/dev/deploys`
       2. 開発の最新成功版 ≠ 検証の最新成功版 →「v0.9.3 を検証環境へ反映しましょう」／「検証環境へ反映する」→ `/dev/deploys`
       3. 自分の担当で `review` がある →「レビュー待ちが {n} 件あります」／「タスクを見る」→ `/dev/tasks`
       4. `checksRunAt` が無い →「自動チェックがまだです」／「自動チェックを実行する」→ `/dev/checks`
       5. どれも無い →「今すぐ対応が必要なものはありません」（ボタンなし）
     - 判定関数は `devUi.ts` に `nextDevAction(state)` として置く
  2. **あなたのタスク**（`SectionTitle` ＋ 一覧。自分の担当で `done` 以外、作業中 → レビュー待ち → 未着手の順、最大 5 件）
     - 1 行: ページ名（body2 650）／ `StatusPill`／ 更新時刻（caption）。行全体がボタン（minHeight 48）で `/dev/tasks` へ
     - 0 件:「担当の未完了タスクはありません」＋「すべてのタスクを見る」
  3. **件数は 1 行に縮める**: `SectionTitle`「構築タスク 全 9 件」の右に、4 状態を `StatusPill` ＋ 件数（tabular-nums）で横並び（折り返し可）。カード 4 枚は削除
- 1440: 左列（次にやること → あなたのタスク）／右列 360px（環境 → 最近のエラー → 品質チェック A 区分）の 2 列（管理者ホームと同じ `minmax(0,1fr) 360px`）
- 390: 次にやること → あなたのタスク → 環境 → エラー → 品質 の 1 列

### D2 【P1】環境カードの「成功」を「最新か」に置き換える
- 問題: 3 環境とも緑の「成功」ピル。実際は 開発 v0.9.3 ／ 検証 v0.9.1 ／ 本番 v0.8.0 と**ずれているのに、全部が問題なしに見える**。「成功」は前回のデプロイ結果で、エンジニアが知りたい「反映が追いついているか」ではない
- 変更: `devUi.ts` に `envSync(dev, env)` を追加（既存の `latestSuccess` から算出。データ変更なし）
  - 開発: 最新デプロイが失敗 → `danger`「前回失敗」／それ以外 `neutral`「最新版」
  - 検証: 開発の最新成功版と一致 → `success`「最新」／不一致 → `warning`「未反映あり」
  - 本番: 検証の最新成功版と一致 → `success`「最新」／不一致 → `warning`「未反映あり」
- 環境は右列の 1 枚の `Surface` 内に 3 行（区切り線）で並べる: 環境名（body2 650）＋ ピル ／ `DevMono lg` のバージョン ／ `DevMono sm` の URL（外部リンクアイコン、minHeight 44）＋ 相対時刻・実行者
- 同じ `envSync` を /dev/deploys のパイプラインでも使う（P1-P1）

### D3 【P2】最近のエラーに対処先を付ける
- 各行の末尾に環境 `StatusPill`（dot なし）と「{count} 回」を `DevMono sm` で。行の補足にエラー/警告の文字ラベルも併記（現状アイコンの aria-label のみ）

## 実装後の確認（デザイン QA）
- 1440 / 390 で 4 ページを撮影し、横はみ出し 0・タップ対象 44px・最初の画面に Primary Action が入ることを確認
- デモの初期状態で: ダッシュボードの次にやること＝「v0.9.3 を検証環境へ反映しましょう」、デプロイ画面で contained は検証のボタンだけ、本番は `Lock`＋理由文
- 検証へ反映 → デザイン未承認状態で本番が「お客様ポータルで承認状況を見る」になること、承認後に本番ボタンが contained になること
- `prefers-reduced-motion` で確認済み一覧の開閉が即時になること
