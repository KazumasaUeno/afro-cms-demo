| 項目 | 内容 |

### 1.3 AI 要件定義の見出しと要約

```
┌ AI 要件定義（会社標準ひな型 v0.1） ─────────────────────────────┐
│ WEBサイト構築 要件定義書ひな型 v0.1 の章立てで、ヒアリングの回答から      │
│ 担当者がまとめました。                                              │

└────────────────────────────────────────────────────┘
```

- 件数は `StatusPill`（文字つき。色だけにしない）。数字は `tabular-nums`。0 件の種類は出さない
- 「確定」には `proposed` の個別・選択（採用案）と追加項目を数える

### 1.4 章の目次と開閉（129 項目への道しるべ）

**デスクトップ（lg 以上）**: 2 列。左 240px が目次（`position: sticky; top: topbar+16`）、右が章の本文。

```
┌ 目次 ───────────┐ ┌ 01 プロジェクト概要・体制        未確定 3  [▲] ┐
│ 01 プロジェクト概要… 3│ │ 案件名     [個別]  ○○株式会社 コーポレートサイト        │
│ 02 業務スコープ   4│ │ 背景・課題 [個別]  採用ページへの応募が少なく…          │
│ 03 サイト基本要件 1│ │ 責任者     [個別]  [未確定] 未確定（ヒアリングで確認します） │
│ …               │ │ 特記事項・対象外・追加費用・承認状況                     │
│ 11 インフラ… 確認中│ │   予算の上限は別途お見積りで確認します。                │
│ …               │ └──────────────────────────────┘
│ 22 未決事項…      │ ┌ 11 インフラ・ホスティング       確認中 8  [▼] ┐
│ 23 標準仕様の管理…  │ │ アフロの標準仕様を適用します（確認中・確定後に記載）      │
└─────────────┘ └──────────────────────────────┘
```

- 目次の行: `章番号 章名`＋右端に未確定の件数（0 なら出さない。固定だけの章は「確認中」）。押すとその章へスクロールし、閉じていれば開く。`<nav aria-label="要件定義書の目次">`、章へ `scroll-margin-top: topbar+16`
- 章: `Surface` 1 枚。見出し行全体が開閉ボタン（`<h3>` の中の `button`、`aria-expanded`・`aria-controls`、高さ 48px 以上）。見出しに未確定・確認中の件数
- **初期の開閉**: md 以上は「固定だけの章（11・14・15）」を閉じ、他は開く。md 未満は全章を閉じる（目次として章見出しの列が見える）。閉じた固定章も 1 行「アフロの標準仕様を適用します（確認中・確定後に記載）」を出す
- 「すべて開く / すべて閉じる」（ページ内検索 Ctrl+F の前に開ける手段）。開閉は `Collapse`、reduced-motion では即時
- 印刷・PDF は開閉に関係なく全部出す（§3）

**モバイル（md 未満）**: 1 列。目次は AI 要件定義の見出しの下に「目次（20 章）」の開閉ボタン → 開くと章の一覧（各行 48px）。各章の末尾に「目次へ戻る」の文字リンク。

```
AI 要件定義（会社標準ひな型 v0.1）
[確定 52][未確定 31][確認中 32]
[目次（20 章）            ▼]
┌ 01 プロジェクト概要・体制 ┐
│ 未確定 3             ▼ │
└───────────────┘
┌ 02 業務スコープ       ┐
│ 未確定 4             ▼ │
└───────────────┘
```

### 1.5 項目 1 行の形

| 幅 | 形 |
|---|---|
| md 以上 | 3 列 grid: 項目名 180px ／ 区分チップ 56px ／ 内容 1fr（`<dl>`: dt＝項目名、dd＝区分＋内容） |
| md 未満 | 1 行目: 項目名（subtitle2）＋区分チップ／2 行目: 状態のチップ＋内容（全幅） |

- 区分チップ: `StatusPill tone="neutral" dot={false}` で「固定」「個別」「選択」（色で区別しない。文字で区別）
- 内容: `body2`、`overflowWrap: anywhere; lineBreak: strict; whiteSpace: pre-wrap`（今の `longText`）。中央揃えにしない

### 1.6 状態ごとの見え方（お客様）

| status / 条件 | チップ | 内容の欄 |
|---|---|---|
| `proposed`・個別 | なし（静かに） | 文 |
| `proposed`・選択 | 「採用案」primary | 文 |
| `proposed` で文が空 | 「未確定」warning | 「未確定（ヒアリングで確認します）」muted |
| `open`（文なし＝材料の無い 48 項目の初期値・担当者が書いていない） | 「未確定」warning | 「未確定（ヒアリングで確認します）」muted |
| `open`（文あり） | 「未確定」warning | 文（途中のメモとして出す） |
| `na`・個別 | 「対象外」neutral | 理由の文 |
| `na`・選択 | 「不採用」neutral | 理由の文 |
| `std_pending`（固定） | 「確認中」info | 「アフロの標準仕様の確定後に記載します」muted＋caption「確認対象: {target}」 |
| 追加項目（`added`） | 「追加項目」neutral＋状態（採用案／不採用） | 文＋caption「追加した理由: {reason}」。章の末尾に並べる |
| カタログに無い id（版の取り違え。§6.1） | 「旧版の項目」neutral | 文。全章の後に「旧版の項目」の章として出す（落とさない） |

- **お客様には出さない**: 「AI追加」の文字（Q-8 決定で「追加項目」）、根拠のチップ、要確認の数字の印、`by`（AI／転記／担当者）
- 章末の「特記事項・対象外・追加費用・承認状況」: 文があるときだけ出す（画面）。16 章は欄自体が無い
- 22 章「未決事項」（t22-01）はサーバーが集めた一覧の文をそのまま（改行を保つ）

- 「お客様の表示を確認」: `Dialog`（md 未満は fullScreen）に §1 の `ProposalV3Body` を出す。要確認の数字だけ `<mark>`（今の `FlaggedText`）。見出しに「確認用プレビュー（お客様には印は出ません）」
- 表紙はひな型どおり文書の頭に置く（§5.1 の「末尾」から変更。PDF の順と揃えるため）[DECISION ui-ux-designer]
- 章の初期の開閉: **提出前に必須の章（01・02・19・21。2026-11-25 決定）と、要確認の数字がある章を開く**。他は閉じる。見出しに「確定案 n／未確定 m／確認中 k」と「要確認の数字 n」（warning）
- 絞り込み（`ToggleButtonGroup`）: 未確定だけ＝`open`・文が空の `proposed`・理由が空の `na`。要確認の数字だけ＝`flags.unsupportedNumbers` が文に残る項目。絞り込み中は該当の無い章を「該当なし」1 行に畳む
- md 未満の目次: 絞り込みの下に「章へ移動」の `TextField select`

### 2.2 区分ごとに直せること（検査の正は `functions/src/ai/reqDocEditable.ts:57-74`）

| 区分 | 状態の選び方 | 文 | 出すもの |
|---|---|---|---|
| **固定** | 出さない（`std_pending` のまま。変えると保存が `invalid-argument`） | 入力欄を出さない。「確認中（標準仕様の確定後に記載）」の文字だけ | 確認対象（caption） |
| 個別 | `ToggleButtonGroup`: 確定案／未確定／対象外 | `TextField` multiline、`{n} / 400文字` | 確認対象（helperText）・根拠のチップ（読み取り専用）・書いた元 |
| 選択 | 採用案／未確定／不採用 | 同上 | 同上 |
| 22 章 未決事項（t22-01） | 個別と同じ | 上限 `REQ_DOC_LIMITS.openItemsText`（4,440 字）、minRows 4 | 同上 |
| AI追加 | 採用案／不採用 | 項目名（1〜40 字・必須）・内容（≤400）・理由（≤200） | 「AI追加」（`AiBadge`）・根拠のチップ・削除ボタン |
| 特記事項（章末。16 章は無し） | — | ≤400 | ラベル「特記事項・対象外・追加費用・承認状況」 |
| 表紙 4 欄 | — | 各 ≤100（1 行） | helperText「会社名と役職まで（氏名は入れません）」 |

- 変えられないもの（画面に操作を出さない）: 固定の状態と文・`by`・根拠・AI追加の章と根拠・**AI追加を新しく足すこと**（Q-8）
- 書いた元（caption・読み取り専用）: `ai`「AI の下書き」／`server`「ヒアリングの選択肢・案件情報から転記」／`human`「担当者が記入」。直しても `by` は変わらない（記録の意味は「最初に誰が置いたか」）
- 対象外・不採用で文が空: 欄に error「対象外（不採用）にするときは理由を書いてください」。**その間は自動保存を送らない**（送ると検査で拒否されるため）。保存の状態に「理由が未入力の項目が {n} 件あります。入力すると保存します」
- AI追加の削除: 確認 `Dialog`「この追加項目を削除しますか？ 作り直さない限り元に戻せません。」［キャンセル］［削除する］。削除ボタンは 44×44、他の操作から 8px 以上離す
- 要確認の数字: 今の `FlagLine` を各欄の直下に（項目単位）

### 2.3 承認を依頼する（v3 で足す止め方）

- 今の止め方（`approvalBlock`）に加えて、**提出前に必須の章（01・02・19・21）に未確定が残る間は押せない**。理由の文: 「01・02・19・21 章に未確定の項目が {n} 件あります。埋めると承認を依頼できます。」＋「未確定だけ表示」へ切り替えるボタン
